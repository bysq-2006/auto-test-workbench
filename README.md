# 自动化测试工作台

通用规范。先锁定结构与协作方式，业务细节和脚本在使用中再长出来。

## 这是什么

一套给「主 AI + 多个子 AI」一起做功能测试的工作台：主 AI 负责任务拆分和最终合成，子 AI 各自在隔离环境里跑测、写结果。浏览器层默认用 Playwright。

## 为什么这样写

原来的临时脚本会慢慢堆成屎山。这里只先约定目录、隔离和文档写法，不提前写死业务步骤。

## 先锁住的规则

1. 待测清单是单一入口。开始测试前，先和主 AI 讨论清楚要测哪些，清单可以先空着。
2. 每个子 AI 只在自己的临时文件夹里写，不直接改同一份总文档。
3. 浏览器端口、标签页、登录态由统一调度系统发放和回收，不靠提示词自行协调。
4. 只分端口不够：窗口隔离用 Playwright 的 browser context 或标签租约。
5. 基础提示词、调度脚本、目录约定放在仓库共用规范里，不要复制进每个临时文件夹，避免慢慢漂掉。
6. 主 AI 合成时只做汇总和冲突检查，不回改各子文件夹里的原始记录。
7. 密钥、账号、token 不进仓库。

## 流程

### 1. 讨论并形成待测清单

`inventory/` 下放清单。刚开始可以为空，讨论后再往里加条目（建议一条用例一个文件，便于认领）。

### 2. 开测时给每个 AI 临时工作区

所有运行中的子 AI 工作区都放在 `runs/` 下，例如 `runs/2026-11-10-auth/`。

每个子 AI 一个子目录，开测时写入：

- 负责的板块
- 分到的清单条目
- 调度系统分配的浏览器端口 / context

### 3. 各自记录结果

每个临时文件夹里写：

- 预期结果
- 实际结果
- 必要的截图或日志（不要包含密码）

### 4. 主 AI 合成

主 AI 把各文件夹结果汇总到总报告，检查冲突和遗漏。原始记录保留在原文件夹，方便对账。

## 目录（初稿）

```
inventory/          待测清单（一条用例一个文件）
runs/               各轮测试的临时工作区
  <run-id>/
    <agent-id>/     该 AI 的预期、实际结果与说明
reports/            主 AI 合成后的报告
scheduler/          浏览器端口 / 标签 / 登录态调度
spec/               更细的规范（从本 README 拆出去）
```

## 浏览器调度（待实现）

统一调度负责：

- 发放和回收调试端口
- 为每个子 AI 提供独立 context 或标签租约
- 避免多个 AI 抢同一个登录态或切走别人的页面

子 AI 只读取自己文件夹里已被写入的端口和租约，不自己去抢。

## 暂不锁死

业务操作步骤、具体系统页面、脚本实现，都等清单和第一次实际使用时再补。
