资源

对应数据表 browsers。用来管理工作台自己启动的浏览器：每个实例独立端口、独立用户数据目录。列表可按状态筛选，也可按端口或使用者搜索。页面以小电脑卡片展示，横排两个，屏幕会按设定间隔抓取对应画面（默认 1 秒）。页面可以启动和关闭；关闭后的卡片可以开机（同一端口重新通电）或删除，用来清掉列表里不再需要的记录。占用和释放主要给接口用。

字段

真实名备注
id主键，自增。
port远程调试端口，由服务端从 9330 起分配，不能自己传。永远不会是 9229。
statusidle（空闲）、occupied（占用）或 closed（已关闭）。closed 是终态。
agent_name当前使用者。空闲和未占用时可空；占用时必填。
pid工作台启动时记下的进程号。关闭时只结束这一个 PID。
user_data_dir该实例的用户数据目录，绝对路径，位于 runs/browsers/ 下，每个实例一份。
created_at创建时间，UTC。
updated_at最近一次状态变更时间，UTC。

隔离规则

每个代理的浏览器互相隔离：独立的 --remote-debugging-port，加上独立的 --user-data-dir，不要用用户默认 Chrome 配置，也不要多个实例共享目录。工作台只管理自己启动的实例。不要去连、附加或操作不是本工作台启动的浏览器。不要探测、连接或结束 9229 上的进程，也不要动用户自己的 Chrome。

后端 API

GET /browsers：查看资源

接收：查询参数 status（可选，idle / occupied / closed）、q（可选，按端口或使用者包含匹配）、limit（默认 10，最大 200）、page（默认 1）。

返回：对象 {items, total, page, limit}。

POST /browsers：启动浏览器

接收：JSON 对象，可以为空。不要传 port，传了返回 400。端口由服务端从 9330 向上找空闲端口（库里没有未关闭记录，且本机当前能绑上），然后启动可见窗口的 Chrome/Chromium。

返回：新建的资源记录，status 为 idle，agent_name 为空，带 id、port、pid、user_data_dir 等。启动失败不会留下一条假装可用的 idle 记录，返回明确错误。

GET /browsers/{id}/screenshot：抓取当前画面

接收：路径里的资源 id。只连接该记录自己的调试端口，不会去连 9229 或用户自己的 Chrome。

返回：当前页面的 JPEG 图片，不缓存。找不到 id 返回 404。已经关闭的返回 400。调试端口连不上或没有可抓的页面返回 502。

POST /browsers/{id}/status：占用、释放或关闭

接收：JSON，status（必填，idle / occupied / closed）、agent_name（占用时必填且非空）。

  • idle：释放。清空 agent_name，进程保持运行。
  • occupied：占用。已被其他代理占用时返回 409，不要抢。同一代理重复占用可以成功。
  • closed：只结束这一条记录对应的、由工作台启动的那个进程，然后把该行标成 closed。进程已经不在了仍标关闭，不因此 500。关闭后端口可以被下一次 POST /browsers 再用。

返回：更新后的资源记录。找不到 id 返回 404。已经是 closed 的再改状态返回 400。

POST /browsers/{id}/power-on：给已关闭的记录开机

用途：卡片已关闭后，右下角会出现「开机」按钮，点一下就是调这个接口——把这台「电脑」重新通电，而不是新建一台。

接收：无请求体。

行为：沿用原记录的 port 和 user_data_dir 重新拉起浏览器，成功后该行回到 idle、agent_name 清空、pid 更新为新进程。端口已被别的进程占掉就返回 409，不会自行换端口——换了就是另一台机器，记录会对不上。

返回：更新后的资源记录。找不到 id 返回 404，未关闭的返回 400，启动失败返回 500。

注意：关闭时会把该实例的 user_data_dir 一起清掉，所以开机拿到的是同一个目录路径、但是空配置——登录态不会自动回来。要保留登录态，就得在关闭时不清目录。

DELETE /browsers/{id}：删除已关闭的记录

用途：清掉列表里不再需要的记录。卡片已关闭后，右下角会出现「删除」按钮，点一下就是调这个接口。

接收：无请求体。

行为：只删除库里的这一行，不结束任何进程——真要结束进程是 closed 做的事。所以只有 closed 的记录能删；未关闭的返回 400，并提示先关闭。删除时会顺手清掉该实例残留的 user_data_dir（如果还在）。

返回：{"id": 3, "deleted": true}。找不到 id 返回 404。
