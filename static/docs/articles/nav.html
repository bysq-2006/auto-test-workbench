导航

点左侧菜单，把浏览器带到指定页面。和手点完全一样——真实鼠标事件走一遍，前端的权限校验、页面初始化、数据加载都会照走。

不用 router.push，也不拼 hash。那样看着跳过去了，页面数据没加载、菜单选中态也不对，属于「假到达」。

怎么写路径

从左边第一条写到具体页面，用 / 分开，也可以传数组。例如：

殡仪管理/殡仪业务管理/殡仪业务办理

这套菜单有两类，行为不一样，路径必须写到叶子：

  • 一级（左侧窄条上的图标项）和带子项的分组：点了只切换菜单组、只展开列表，地址不变。
  • 叶子（分组下面的具体页面）：点了才真跳，地址会变。

所以只写 殡仪管理 或 殡仪管理/殡仪业务管理 会返回 409，并把下一级能选的页面列在 visible 里，照着补一级就行。

多快

实测跨模块走三级（含两次菜单展开）平均 0.5~0.9 秒，同一页再调一次 0.1 秒以内。已经在目标页时直接返回，clicks 是 0，不会重复点击触发刷新。

后端 API

POST /navigate：点到指定位置

接收：JSON。

字段备注
path必填。字符串（"殡仪管理/殡仪业务办理"）或数组（["殡仪管理", "殡仪业务办理"]），最多 4 级。
port可选，调试端口。不传就自己找一台还活着的浏览器。
browser_id可选，按资源页的记录 id 指定。
timeout可选，整条路径的总预算，默认 4 秒。

返回：成功 200。

字段备注
oktrue 表示已经停在目标页面上。
url当前地址。
active菜单里当前选中项的文本。
ms内部耗时，毫秒。
clicks实际点了几下。已经在该页时是 0。
steps每一级的文本、耗时、是否让地址变化。
note提示，比如「已经在该页面，未点击」。

失败时

返回 409，正文里带 reason、failed_at、visible（当时能看见的菜单），按原因分四种：

  • 找不到某一级：visible 里是当前能看见的名字，核对写法。
  • 最后一段是分组：visible 里是它下面能选的页面。
  • 点了但下一级没出现：多半是路径写错，或者这一级还在加载。
  • 点到了但没换页：返回里 note 会说，一般是同页内的切换。

连不上调试端口返回 502，没有可用浏览器返回 409。

例子

curl -s -X POST http://127.0.0.1:8000/navigate \
  -H "Content-Type: application/json" \
  -d "{\"path\":\"殡仪管理/殡仪业务管理/殡仪业务办理\"}"

要指定某台机器就加 "port": 9333。Windows 的 curl 里 JSON 带反斜杠容易报 422，复杂请求建议用 --data-binary @文件。
