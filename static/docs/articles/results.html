结果

对应数据表 test_results。各子代理把干完的结果回写到这里，不限于测试。用 kind 区分类型：test 是测试结果，要带通过或失败；note 是通用结果，不用带状态。可以挂到某个任务或技能上，也可以都不挂。

字段

真实名备注
id主键，自增。
agent_name回写这条结果的代理名。
kindtest（测试）或 note（通用）。不传时默认 test。
task_id可选，关联任务。任务被删除时这里会置空，结果还在。
skill_path可选，对应技能脚本的相对路径。技能不在库里，这里只是记下路径；脚本被删掉后路径仍会留着。
status测试结果为 pass 或 fail；通用结果为空。
summary结果内容或摘要，可空。
log_text详细日志，可空。
recorded主 AI 是否已经记录过这条。默认 false。
created_at回写时间，UTC。

后端 API

GET /results：查看结果

接收：查询参数 kind（可选，test 或 note）、recorded（可选，true 或 false）、q（可选，按代理名、类型、状态、内容、任务标题等包含匹配）、limit（默认 10，最大 200）、page（默认 1）。

返回：对象 {items, total, page, limit}。items 为结果数组。除表字段外，还会带上 skill_name、task_title（根据当前技能目录和任务表补上）。

POST /results：回写结果

接收：JSON，agent_name（必填）、kind（可选，默认 test）、status（kind 为 test 时必填，pass 或 fail；通用结果不要传）、task_id / skill（可选，skill 可写路径、文件名或技能名，见「技能」页）、summary、log_text。

返回：新建的结果。如果填写的任务不存在，或技能在目录里找不到，返回 400。

POST /results/{id}/recorded：标记主 AI 是否已记录

接收：JSON，recorded（必填，true 或 false）。

返回：更新后的结果。找不到这条时返回 404。
