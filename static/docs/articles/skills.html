技能

技能不进数据库。每次调用接口都会递归扫描 skills/ 下的 *.py，只读文件内容，不会执行脚本。改技能就是在这个目录里增删或改脚本，子目录里的脚本同样能扫到。

技能是公共库，不分轮次：换一轮测试照旧用同一批脚本，不用复制一份到新轮目录里。

下面两类不算技能，不会出现在列表里：

  • 下划线开头的文件和目录，如 _draft/、__pycache__。
  • 固定名字的公共库目录，见下一节。

公共库

skills/ 顶层叫 lib 的目录是公共库，整棵子树都不扫，里面的模块只供技能脚本 import，看不出是技能。目录现在还是空的，旧脚本已整体删掉，从零开始写。

规则只看目录名，不看 __init__.py。以前靠有没有 __init__.py 猜哪个目录是包，副作用是一个包只要补了 __init__.py，整个目录里的脚本会突然从技能列表里消失。

介绍写在文件内部，按下面的顺序读取：

  • 如果写了 SKILL = {"name": "...", "description": "..."}（带类型注解的 SKILL: dict = {...} 也算），优先用这里的名字和介绍。
  • 否则，技能名用文件名（不含 .py），介绍用文件开头的模块文档字符串。

作为参数引用技能

任务和结果都不存技能 id，只记 skill_path 文本。创建任务或回写结果时，skill 参数可以写下面任意一种，服务端都能解析到同一个脚本：

  • 完整路径：skills/echo_check.py、skills/sub/inner.py
  • 相对 skills/ 的路径：sub/inner.py
  • 带后缀的文件名：echo_check.py
  • 不带后缀的名字：echo_check
  • SKILL 里写的 name

解析不到就返回 400。脚本被删掉后，历史记录里的 skill_path 仍然保留，返回里补的 skill_name 会退回用路径里的文件名。

返回字段

真实名备注
name技能名，来自 SKILL 或文件名。
description介绍，来自 SKILL 或模块文档字符串。
path相对路径，比如 skills/echo_check.py。

后端 API

GET /skills：列出当前技能

接收：查询参数 q（可选，按名称、路径、介绍包含匹配）、limit（默认 10，最大 200）、page（默认 1）。

返回：对象 {items, total, page, limit}。items 里每项包含 name、description、path。没有写入接口。
