任务

对应数据表 tasks。任务是给子代理派的活：先创建，再被认领，最后改状态。结果里的 task_id 可以挂到这里的某条任务上。

每条任务都属于某一轮（见「轮次」页）。round_id 是必填的，服务端不会替你猜——没有「当前轮」这种隐式状态，从 AI 从任务详情里就能拿到归属。

字段

真实名备注
id主键，自增。回写结果时用这个当 task_id。
title任务标题。
description可选，任务描述。
statuspending、running、done 或 failed。新建后是 pending。
agent_name认领或负责这个任务的代理名，未认领时可空。和结果表里的 agent_name 是同一个意思。
skill_path可选，对应技能脚本的相对路径。
payload可选，创建时附带的参数，JSON 文本。
round_id所属轮次，必填。升级前的旧数据可能为空（界面上算「未归类」）。
created_at创建时间，UTC。
updated_at最近一次状态或认领变更时间，UTC。

后端 API

GET /tasks：查看任务

接收：查询参数 status（可选）、round（可选，轮次编号；none 查未归类；all 或不传表示不限轮次）、q（可选，按标题、描述、负责人或技能路径包含匹配）、limit（默认 10，最大 200）、page（默认 1）。

返回：对象 {items, total, page, limit}。除表字段外，还会带上 skill_name（根据当前技能目录补上）和 round_name。

POST /tasks：创建任务

接收：JSON，title（必填）、round_id（必填，轮次编号）、description（可选）、skill（可选，路径、文件名或技能名，写法见「技能」页）、payload（可选）。新建后状态是 pending。

返回：新建的任务。缺 round_id、轮次不存在返回 400；轮次已关闭返回 409；技能在目录里找不到时返回 400。

POST /tasks/{id}/claim：认领任务

接收：JSON，agent_name（必填）。只有 pending 的任务能被认领，成功后变成 running。

返回：更新后的任务。已被别人认领时返回 409；任务所在轮次已关闭也返回 409。

POST /tasks/{id}/status：改任务状态

接收：JSON，status（必填，pending / running / done / failed）、agent_name（可选）。标成 running 时必须有 agent_name；改回 pending 会清掉负责人。

返回：更新后的任务。轮次已关闭返回 409。

DELETE /tasks/{id}：删除任务

返回：成功 204，没有正文；任务不存在返回 404。

删任务不连带删结果。挂在这条任务上的结果会保留，只是 task_id 被置空（外键 ON DELETE SET NULL），列表里「绑定的任务」一栏变成 —。
